Skill 清单

不按仓库排，按写一个站点的顺序排。每一阶段挂该阶段真正用得上的 skill，没有对口的就写「暂无」，不凑数。

6 stages · 4 skills
先知道有哪些 不知道有什么 skill 可装时，翻索引： VoltAgent / awesome-agent-skills ↗
STAGE 01

定需求

把一句话需求拆成页面清单和可判定的验收

doc-coauthoring开源

和 AI 一起把需求文档写出来：先问清边界，再逐节对齐，最后成稿。

交付 requirements.md 的骨架与验收清单

装/plugin marketplace add anthropics/skills /plugin install document-skills@anthropic-agent-skills
用「用 doc-coauthoring 和我一起写这份需求，每节先问再写」
坑它擅长长文协作，不是用来出代码的；需求没边界时它会反问很多轮，别指望一句话出稿。
STAGE 02

起骨架

目录、路由、第一个能跑的页面

web-artifacts-builder开源

直接生成可运行的前端产物：HTML、样式、脚本成套给出，而不是一段段碎片。

交付 首页、列表、详情、404 四条路由的空壳

装/plugin marketplace add anthropics/skills /plugin install example-skills@anthropic-agent-skills
用「用 web-artifacts-builder 搭四条路由的空壳，先不写内容」
坑它偏爱单文件产物；要真实工程结构时得明确说「用 Vite + 多文件目录」。
STAGE 03

搭界面

先把版式与 token 定死，再让 AI 生成页面

frontend-design开源

界面结构、组件形态、排版节奏这一层的判断力，避免生成千篇一律的模板脸。

交付 三页的界面结构方案，配色与圆角仍从主站 token 取

装/plugin install example-skills@anthropic-agent-skills
用「用 frontend-design 定版式，参考站内已有的间距和圆角」
坑它给的是设计判断，不是 token；token 要自己先落下，否则每个页面各写一套数值。
STAGE 04

接数据

表、权限、登录，三样都要能用

该阶段暂无对口 skill。表结构与权限是项目自身的知识，交给 Supabase 的迁移与 SDK 更稳，别让 skill 猜你的业务规则。
STAGE 05

上线

CI、部署、深链回退

该阶段暂无对口 skill。构建与部署的可重复性靠流水线保证，见 Coolify；skill 在这里帮不上忙。
STAGE 06

验收

让 AI 自己点页面、截图、断言

webapp-testing开源

驱动浏览器真的打开页面、点按钮、读状态、截图，把「看起来没问题」变成可重跑的断言。

交付 核心路径的 e2e 用例与截图

装/plugin install example-skills@anthropic-agent-skills
用「用 webapp-testing 跑一遍进入列表、开详情、返回首页，截图给我」
坑它会真开浏览器，本机没有 Playwright 依赖时会报错；先装依赖再让它跑。
写自己的：官方仓里带 skill-creator，照着它把项目内的固定流程写成 SKILL.md 即可。
克制一点：同一阶段挂超过两个 skill 会互相抢上下文，宁可少装。
