Vibe Coding 全流程

左边六个阶段，点一个，右边就是这一步的全部：做什么、用什么工具、得到什么、怎么判过关。每段提示词都能直接粘给 agent——它先反问需求，再按这一阶段动手实现。

四个阶段有对口 skill，另外两个没有；不凑数，用工具顶。

STAGE 01

定需求

规则只有一条：验收不过就退回上一阶段，别带着问题往下走。工具不必全装，够用就停。 做完站点想顺手做条宣传片：MoneyPrinterTurbo ↗（开源，给主题自动出短视频）

目标

需求文档能直接拿去排期：出现「好看」「流畅」这类词就算没写完。

步骤 · 做什么 / 用什么 / 得到什么

  • 01

    先写一句可验收的总目标：谁，在什么页面，做成什么，怎么算成功。

    手写，不用工具→ 得到「总目标」一节
  • 02

    列页面清单，最多五页，每页一行用途。

    → 得到页面清单（≤5）
  • 03

    写三条明确不做的功能，把范围钉死。

    → 得到「不做」边界·省掉后期返工
  • 04

    把验收写成可观测现象：点一下出现什么、刷新后还剩什么。

    doc-coauthoring→ 得到 requirements.md

验收

  • 每条需求都对应一个可观测结果
  • 页面清单不超过 5 页，能画在一张纸上
  • 文档里零个主观形容词

常见翻车

需求写成散文，写着写着开始想配色——这时候退回去，先把页面清单定完。

本阶段 skill

doc-coauthoring开源 仓库 ↗

和 AI 一起把需求文档写出来：先问清边界，再逐节对齐，最后成稿。

装
/plugin marketplace add anthropics/skills/plugin install document-skills@anthropic-agent-skills
用
「用 doc-coauthoring 和我一起写这份需求，每节先问再写」
坑
它擅长长文协作，不出代码；需求没边界时会反问很多轮，别指望一句话出稿。

让 AI 先问你：本阶段提示词

你是我的 Vibe Coding 搭档，现在在第 1 阶段「定需求」。这一阶段不写代码、不画界面。

请先用提问把需求问清楚：一次最多问 3 个问题，每个问题给 2–3 个选项并说明影响；我答完再问下一组。
按这个顺序问：
1) 这站点给谁用，他们为什么会打开；
2) 一共几个页面，每页一句话用途；
3) 必须有的三个功能，按优先级排；
4) 明确不做的功能（至少三条）；
5) 每个功能怎么算做完，用可观测现象描述；
6) 有没有参考站点或明确反感的风格。

我回答含糊时（「好看」「流畅」「差不多」）继续追问，直到能验收。
问完用 200 字复述「目标 / 页面清单 / 不做 / 验收」，等我确认，再输出 requirements.md。

把这段发给任意 AI（Claude / Codex / Cursor 都行），它会先反问，不会直接开始写。

目标

四条路由都能打开，页面空着但不报错，可以往上堆内容。

步骤 · 做什么 / 用什么 / 得到什么

  • 01

    初始化工程，定技术栈与包管理器。

    OpenCode→ 得到 package.json 与目录
  • 02

    定四条路由与对应文件：首页、列表、详情、404。

    Vite→ 得到 4 个页面文件
  • 03

    按职责分目录：页面、组件、数据访问、工具函数。

    → 得到不交叉的目录结构
  • 04

    起 dev，每页放一句占位文字，确认能跳转。

    → 得到可跑空壳
  • 05

    跑一次 build，立刻提交第一个 commit。

    → 得到干净基线

验收

  • dev 与 build 都零报错
  • 四条路由全部 200，控制台零 error
  • 改一行字，热更新 1 秒内生效

常见翻车

骨架阶段就开始写样式，目录越铺越乱；先把路由与目录定死，样式留到下一阶段。

本阶段 skill

web-artifacts-builder开源 仓库 ↗

直接生成可运行的前端产物：HTML、样式、脚本成套给出，而不是一段段碎片。

装
/plugin marketplace add anthropics/skills/plugin install example-skills@anthropic-agent-skills
用
「用 web-artifacts-builder 搭四条路由的空壳，先不写内容」
坑
它偏爱单文件产物；要真实工程结构得明确说「用 Vite + 多文件目录」。

让 AI 先问你：本阶段提示词

你在第 2 阶段「起骨架」。目标只是把空壳跑通，不写内容和样式。

先问我：
1) 技术栈与包管理器（Vue + Vite / React + Next / 纯静态）；
2) 页面路由清单，每页对应什么文件名；
3) 目录怎么分（页面 / 组件 / 数据 / 工具）；
4) 部署目标（GitHub Pages / Vercel / 自己的服务器）；
5) 我机器上现有什么环境。

问完再动手：初始化工程 → 建路由与占位页 → 起 dev 确认每页能开 → build 一次 → 提交第一个 commit。
每做完一步，告诉我动了哪些文件、怎么验证，等我确认再下一步。

把这段发给任意 AI（Claude / Codex / Cursor 都行），它会先反问，不会直接开始写。

目标

三个页面各就各位，颜色、间距、圆角只从一套 token 里取。

步骤 · 做什么 / 用什么 / 得到什么

  • 01

    先定 tokens：主色、纸底、四级灰阶、间距刻度、圆角。

    Astryx→ 得到 design-tokens.md
  • 02

    按需装组件，不自造按钮和输入框。

    shadcn/ui→ 得到组件目录
  • 03

    写样式层与断点：桌面、平板、手机三档。

    Tailwind CSS→ 得到样式与断点
  • 04

    图标统一一套，只用一个线条风格。

    Lucide→ 得到图标清单
  • 05

    写三页真实内容：首页讲清是谁，列表能扫读，详情能读完。

    → 得到 首页 / 列表 / 详情
  • 06

    补动效：先叫得出名字，再决定用不用。

    Motion动效手册 ↗→ 得到交互脚本

验收

  • 代码里没有裸数值，全部走 token
  • 390 宽无横向滚动，字号不缩水
  • hover / focus / active 三态齐全
  • 键盘 Tab 能走完整页，焦点看得见

常见翻车

先写样式再想内容，每个页面都要返工；内容先落，样式跟着内容长。

本阶段 skill

frontend-design开源 仓库 ↗

界面结构、组件形态、排版节奏这一层的判断力，避免生成千篇一律的模板脸。

装
/plugin install example-skills@anthropic-agent-skills
用
「用 frontend-design 定版式，参考站内已有的间距和圆角」
坑
它给的是设计判断，不是 token；token 要自己先落下，否则每页各写一套数值。

找方向看 设计参考 ↗，挑动效看 动效手册 ↗。

让 AI 先问你：本阶段提示词

你在第 3 阶段「搭界面」。先把约束问清，再生成页面。

先问我：
1) 想要的调性（暖白纸感 / 冷灰极简 / 高对比）；
2) 主色和一个强调色；
3) 字体偏好（衬线标题还是全无衬线）；
4) 圆角与间距偏松还是偏紧；
5) 三个页面各自的重点内容；
6) 想加的动效名字，不确定就让我从动效手册里挑；
7) 移动端最窄要支持到多少宽。

问完先给 design-tokens（颜色 / 字号 / 间距 / 圆角 / 断点），我确认后再逐页生成。
生成时只允许用 token 里的值，不要出现裸数值；每页给我桌面和 390 宽两张截图。

把这段发给任意 AI（Claude / Codex / Cursor 都行），它会先反问，不会直接开始写。

目标

换一台机器照 README 就能跑起来，没登录的人进不了受限页。

步骤 · 做什么 / 用什么 / 得到什么

  • 01

    建 schema：先写实体和关系，别先写页面需要的字段。

    Supabase→ 得到迁移脚本
  • 02

    开权限策略：默认拒绝，逐条放行。

    → 得到策略表
  • 03

    写数据访问层，页面不直接拼 SQL。

    → 得到 api 封装
  • 04

    接登录与会话，做登录页与「我的」页。

    → 得到登录页与重置密码
  • 05

    补空态与错误态：没数据时说什么，失败时给什么出口。

    → 得到空态 / 错误态组件
  • 06

    写 env 样例与 README，把启动步骤压到三步。

    → 得到 env.example 与 README

验收

  • 新环境照 README 三步能起来
  • 列表空态有文案，失败有提示，不白屏
  • 未登录访问受限页被拦回登录

常见翻车

先开全表权限后补策略，等于线上裸奔；权限从「全拒绝」反向加。

本阶段 skill

该阶段暂无对口 skill。表结构与权限是项目自身知识，交给 Supabase 的迁移与 SDK 更稳，别让 skill 猜你的业务规则。

让 AI 先问你：本阶段提示词

你在第 4 阶段「接数据」。

先问我：
1) 要存哪几类数据，各有哪些字段；
2) 谁可以读写，哪些页面必须登录；
3) 登录方式（邮箱 / 第三方 / 免登录只存本地）；
4) 没数据时的空态文案；
5) 数据出错时给用户什么出口。

问清后按顺序做：建表与迁移 → 权限默认全拒绝再逐条放行 → 数据访问层 → 登录与会话 → 空态与错误态 → env.example 与三步启动的 README。
不要替我的业务规则做假设，缺信息就回来问我。

把这段发给任意 AI（Claude / Codex / Cursor 都行），它会先反问，不会直接开始写。

目标

一条流水线把代码推到线上，出问题能一步回滚。

步骤 · 做什么 / 用什么 / 得到什么

  • 01

    先定体积预算：首屏 JS 多少、图片多大，写进 README。

    → 得到预算表
  • 02

    写 CI：装依赖、跑测试、构建，三件事按顺序。

    → 得到工作流文件
  • 03

    部署：容器或静态产物，按项目选。

    Coolify→ 得到线上站点
  • 04

    配深链回退：任何子路径都回到入口页。

    → 得到 404 回退规则
  • 05

    接域名与 HTTPS，把 http 跳转一次做完。

    → 得到证书与跳转
  • 06

    做首屏体检：体积、请求数、首字时间。

    → 得到体检记录

验收

  • 线上首屏可打开，全站 HTTPS
  • 随手复制内页链接刷新不 404
  • 首屏 JS 不超过 120KB gzip

常见翻车

只测首页，深链一刷新就 404；上线前先手点三个内页。

本阶段 skill

该阶段暂无对口 skill。构建与部署的可重复性靠流水线保证，见 Coolify；skill 在这里帮不上忙。

让 AI 先问你：本阶段提示词

你在第 5 阶段「上线」。

先问我：
1) 托管在哪（GitHub Pages / Vercel / 自己的服务器）；
2) 有没有域名和 HTTPS 需求；
3) 是否需要 CI（装依赖 → 测试 → 构建）；
4) 首屏体积预算；
5) 出问题怎么回滚。

问完按顺序做：定体积预算 → 写 CI → 部署 → 配深链回退 → 域名与 HTTPS → 首屏体检。
每一步给出可验证的结果（URL、构建日志、体积数字），不要只说「已完成」。

把这段发给任意 AI（Claude / Codex / Cursor 都行），它会先反问，不会直接开始写。

目标

核心路径一条命令能重跑，红了就知道哪一步断了。

步骤 · 做什么 / 用什么 / 得到什么

  • 01

    单元测试只测纯逻辑：解析、格式化、计算。

    Vitest→ 得到单元用例
  • 02

    e2e 只测三条：进入、登录、增删一条数据。

    Playwright→ 得到 e2e 用例
  • 03

    写冒烟清单：上线前手点的十件事。

    → 得到 checklist
  • 04

    清调试代码：console.log、假数据、临时开关。

    → 得到干净构建
  • 05

    记已知问题，别用「以后再说」口头传。

    → 得到 issues 清单

验收

  • CI 全绿，e2e 可本地一条命令重跑
  • 控制台零 error，无 404 资源
  • 源码里搜不到 console.log 与 TODO 占位

常见翻车

e2e 写得比业务还多，维护成本压过收益；只测会真的坏的那几条。

本阶段 skill

webapp-testing开源 仓库 ↗

驱动浏览器真的打开页面、点按钮、读状态、截图，把「看起来没问题」变成可重跑的断言。

装
/plugin install example-skills@anthropic-agent-skills
用
「用 webapp-testing 跑一遍进入列表、开详情、返回首页，截图给我」
坑
它会真开浏览器，本机没有 Playwright 依赖时会报错；先装依赖再让它跑。

让 AI 先问你：本阶段提示词

你在第 6 阶段「验收」。目标是把「我看着没问题」换成可重跑的检查。

先问我：
1) 哪三条路径坏了最致命；
2) 用 Playwright 还是手工清单；
3) 单元测试覆盖哪些纯逻辑；
4) 上线前必须手点的十件事；
5) 已知问题里哪些可以留到下一版。

问完再做：写单元用例 → 写三条 e2e → 出冒烟清单 → 清调试代码 → 列已知问题。
最后给我一份「跑一次要多久、红了怎么定位」的说明；验收不过的项，建议退回上一阶段。
