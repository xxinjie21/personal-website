目标

需求文档能直接拿来排期，不出现「好看」「流畅」这类没法验收的词。

步骤

01

先写一句可验收的总目标：谁，在什么页面，做成什么，怎么算成功。

→ 得到「总目标」一节
02

列页面清单，最多五页，每页一行用途。

→ 得到页面清单（≤5）
03

写三条明确不做的功能，把范围钉死。

→ 得到「不做」边界·省掉后期返工
04

把验收写成可观测现象：点击后出现什么、刷新后还剩什么。

→ 得到验收清单 requirements.md

验收

  • 每条需求都对应一个可观测结果
  • 页面清单不超过 5 页，能画在一张纸上
  • 文档里零个主观形容词

常见翻车

需求写成散文，写着写着开始想配色——这时候退回去，先把页面清单定完。

下一步02 起骨架 ↓看该阶段的 skill ↗

目标

四条路由都能打开，页面是空的但不报错，可以往上堆内容。

步骤

01

初始化工程，定技术栈与包管理器。

→ OpenCode得到 package.json 与目录
02

定四条路由与对应文件：首页、列表、详情、404。

→ Vite得到 4 个页面文件
03

按职责分目录：页面、组件、数据访问、工具函数。

→ 得到不交叉的目录结构
04

起 dev，每页放一句占位文字，确认能跳转。

→ 得到可跑空壳
05

跑一次 build，立刻提交第一个 commit。

→ 得到干净基线

验收

  • dev 与 build 都零报错
  • 四条路由全部 200，控制台零 error
  • 改一行字，热更新 1 秒内生效

常见翻车

骨架阶段就开始写样式，目录越铺越乱；先把路由与目录定死，样式留到下一阶段。

上下游↑ 0103 搭界面 ↓

目标

三个页面各就各位，颜色、间距、圆角只从一套 token 里取。

步骤

01

先定 tokens：主色、纸底、四级灰阶、间距刻度、圆角。

→ Astryx得到 design-tokens.md
02

按需装组件，不自造按钮和输入框。

→ shadcn/ui得到组件目录
03

写样式层与断点：桌面、平板、手机三档。

→ Tailwind CSS得到样式与断点
04

图标统一一套，只用一个线条风格。

→ Lucide得到图标清单
05

写三页真实内容：首页讲清是谁，列表能扫读，详情能读完。

→ 得到 首页 / 列表 / 详情
06

补动效：先叫得出名字，再决定用不用。

→ Motion动效手册 ↗得到交互脚本

验收

  • 代码里没有裸数值，全部走 token
  • 390 宽无横向滚动，字号不缩水
  • hover / focus / active 三态齐全
  • 键盘 Tab 能走完整页，焦点看得见

常见翻车

先写样式再想内容，每个页面都要返工；内容先落，样式跟着内容长。

上下游↑ 0204 接数据 ↓

目标

换一台机器照 README 就能跑起来，没登录的人进不了受限页。

步骤

01

建 schema：先写实体和关系，别先写页面需要的字段。

→ Supabase得到迁移脚本
02

开权限策略：默认拒绝，逐条放行。

→ 得到策略表
03

写数据访问层，页面不直接拼 SQL。

→ 得到 api 封装
04

接登录与会话，做登录页与「我的」页。

→ 得到登录页与重置密码
05

补空态与错误态：没数据时说什么，失败时给什么出口。

→ 得到空态 / 错误态组件
06

写 env 样例与 README，把启动步骤压到三步。

→ 得到 env.example 与 README

验收

  • 新环境照 README 三步能起来
  • 列表空态有文案，失败有提示，不白屏
  • 未登录访问受限页被拦回登录

常见翻车

先开全表权限后补策略，等于线上裸奔；权限从「全拒绝」反向加。

上下游↑ 0305 上线 ↓

目标

一条流水线把代码推到线上，出问题能一步回滚。

步骤

01

先定体积预算：首屏 JS 多少、图片多大，写进 README。

→ 得到预算表
02

写 CI：装依赖、跑测试、构建，三件事按顺序。

→ 得到工作流文件
03

部署：容器或静态产物，按项目选。

→ Coolify得到线上站点
04

配深链回退：任何子路径都回到入口页。

→ 得到 404 回退规则
05

接域名与 HTTPS，把 http 跳转一次做完。

→ 得到证书与跳转
06

做首屏体检：体积、请求数、首字时间。

→ 得到体检记录

验收

  • 线上首屏可打开，全站 HTTPS
  • 随手复制内页链接刷新不 404
  • 首屏 JS 不超过 120KB gzip

常见翻车

只测首页，深链一刷新就 404；上线前先手点三个内页。

上下游↑ 0406 验收 ↓

目标

核心路径一条命令能重跑，红了就知道哪一步断了。

步骤

01

单元测试只测纯逻辑：解析、格式化、计算。

→ Vitest得到单元用例
02

e2e 只测三条：进入、登录、增删一条数据。

→ Playwright得到 e2e 用例
03

写冒烟清单：上线前手点的十件事。

→ 得到 checklist
04

清调试代码：console.log、假数据、临时开关。

→ 得到干净构建
05

记已知问题，别用「以后再说」口头传。

→ 得到 issues 清单

验收

  • CI 全绿，e2e 可本地一条命令重跑
  • 控制台零 error，无 404 资源
  • 源码里搜不到 console.log 与 TODO 占位

常见翻车

e2e 写得比业务还多，维护成本压过收益；只测会真的坏的那几条。
